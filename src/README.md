# src

## Overview

`src/` is the frontend runtime and build-time rendering boundary for the Air2Growth site. TypeScript modules map German and English routes, load and apply locale catalogs, expand the HTML template manifest, and render SEO metadata. Browser modules progressively enhance the rendered pages with language-link maintenance, navigation and hero behavior, supporter controls, and the illustrated function tour. `main.ts` is the Vite entry that imports the styling pipeline and starts the optional browser enhancements; the JSON files under `locales/` provide translation data consumed by these modules.

## Interface

- [`locale-paths.ts`](./locale-paths.ts): exports `LOCALES`, `Locale`, `DEFAULT_LOCALE`, `PAGE_PATHS`, `isLocale`, `localeFile`, and `localizedHref` ([`locale-paths.ts:LOCALES`], [`locale-paths.ts:PAGE_PATHS`]). The route table is the shared source for localized page paths.
- [`i18n-html.ts`](./i18n-html.ts): exports `Catalog`, `LOCALES_DIR`, `decodeText`, `translationKey`, `escapeText`, `loadCatalog`, `translateHtml`, `localizeHtml`, and `languageSwitcher` ([`i18n-html.ts:loadCatalog`], [`i18n-html.ts:translateHtml`]). These functions load the fixed locale catalogs and translate visible HTML text and supported accessible attributes.
- [`render.ts`](./render.ts): exports `TEMPLATES_DIR`, `PARTIALS_DIR`, `MANIFEST`, `renderTemplate`, and `renderShell` ([`render.ts:MANIFEST`], [`render.ts:renderShell`]). The renderer expands allow-listed template includes, applies localization, inserts breadcrumbs and language links, and replaces the SEO marker.
- [`seo.ts`](./seo.ts): exports `SITE_URL`, `SEO_PAGES`, `LocalizedPage`, `SITE_PAGES`, `renderSitemap`, `canonicalRedirect`, `pageBreadcrumbs`, `renderBreadcrumbs`, and `renderSeoTags` ([`seo.ts:SITE_PAGES`], [`seo.ts:renderSeoTags`]). These values and functions define the localized canonical URL, breadcrumb, sitemap, metadata, Open Graph, Twitter, and JSON-LD boundaries.
- [`messages.ts`](./messages.ts): exports `message` ([`messages.ts:message`]), which resolves runtime copy from the German or English catalogs and substitutes named placeholders.
- [`main.ts`](./main.ts): browser entry point with no exported API. It imports the shared styling modules (`styles.css`, `redesign.css`, `solution.css`, `editorial.css`, `function-tour.css`, and `supporters.css`), starts `initLanguageLinks`, then lazy-loads `initSupporters` and `initFunctionTour` only when their data roots are present ([`main.ts:initLanguageLinks`], [`main.ts:initSupporters`], [`main.ts:initFunctionTour`]).
- [`locale-browser.js`](./locale-browser.js): exports `initLanguageLinks` ([`locale-browser.js:initLanguageLinks`]), which keeps `data-locale-link` destinations aligned with the current query and hash and returns an abort cleanup function.
- [`hero-loading.js`](./hero-loading.js): exports `scheduleHeroVideo` ([`hero-loading.js:scheduleHeroVideo`]), a poster-first startup scheduler that accepts a hero element, a start callback, and an optional browser environment.
- [`site.js`](./site.js): side-effect-only browser module. It owns the `#mobile-menu` overlay, htmx status/error handling, and the decorative `[data-hero-video]` double-buffer playlist; it exports no symbols ([`site.js:#mobile-menu`], [`site.js:data-hero-video`]).
- [`experience.js`](./experience.js): side-effect-only progressive enhancements for moved homepage anchors, reduced-motion hero entrance animations, and scroll-aware section navigation ([`experience.js:redirectMovedHomeSection`], [`experience.js:updateNavigation`]).
- [`function-tour.js`](./function-tour.js): exports `TOUR_SCENES`, `TOUR_DURATION`, `formatTourTime`, `sceneAt`, and `initFunctionTour` ([`function-tour.js:TOUR_SCENES`], [`function-tour.js:initFunctionTour`]). The initializer wires the GSAP/ScrollTrigger illustrated tour to the supplied root element.
- [`supporters.js`](./supporters.js): exports `initSupporters` ([`supporters.js:initSupporters`]), which adds keyboard and button scrolling to the supporter-logo viewport and returns cleanup.

## Invariants

- [`locale-paths.ts:LOCALES`] contains exactly `de` and `en`, with `de` as [`locale-paths.ts:DEFAULT_LOCALE`]. [`locale-paths.ts:PAGE_PATHS`] is the canonical mapping for all page shells; [`locale-paths.ts:localizedHref`] preserves external and non-root-relative URLs and only rewrites known internal page paths.
- [`i18n-html.ts:loadCatalog`] reads a fixed file list for each locale and merges catalogs in order. [`i18n-html.ts:translateHtml`] translates text and `alt`, `aria-label`, `placeholder`, and `title` attributes while leaving comments, scripts, styles, tags, IDs, classes, links, and animation hooks intact. [`i18n-html.ts:localizeHtml`] sets the document language, localizes internal links, adds a hidden `lang` form field, and selects localized diagram assets.
- [`render.ts:MANIFEST`] is the only include allow-list. [`render.ts:renderTemplate`] permits at most five include-expansion passes, throws for unknown include names, and throws if markers remain unresolved. [`render.ts:renderShell`] requires exactly one `<!-- @seo -->` marker after localization and breadcrumb/language expansion.
- [`seo.ts:SITE_PAGES`] is derived from every [`seo.ts:SEO_PAGES`] shell for both locales, and each page keeps a locale-specific canonical path, aliases, language, and shell file. [`seo.ts:canonicalRedirect`], [`seo.ts:renderSitemap`], and [`seo.ts:renderSeoTags`] all use the same [`seo.ts:SITE_URL`] and [`locale-paths.ts:PAGE_PATHS`] data, so aliases, canonical tags, alternates, sitemap entries, breadcrumbs, and JSON-LD cannot choose independent destinations.
- [`messages.ts:message`] falls back to the source string when a catalog key is absent and leaves unknown `{placeholder}` names unchanged. Its default locale is derived from the document language when a browser document exists, otherwise German is used.
- Browser enhancements remain optional: [`supporters.js:initSupporters`] returns a no-op cleanup when required controls are absent, [`function-tour.js:initFunctionTour`] is activated only for a matching root by [`main.ts`], and [`site.js:data-hero-video`] leaves the poster/fallback content available when no hero video exists or [`site.js:giveUpToFallbackInitial`] exhausts initial playback candidates.
- [`function-tour.js:TOUR_SCENES`] is the single absolute-second timing manifest used for timeline labels, scene selection, progress text, and reduced-motion still frames. [`function-tour.js:sceneAt`] always clamps a time at or beyond the final scene to the final scene index.
- [`hero-loading.js:scheduleHeroVideo`] does not start the decorative video until the page and poster are ready, two animation frames have allowed the initial content to paint, the hero is visible, and reduced-motion/data-saving/network checks pass. It starts at most once and its returned cleanup cancels pending listeners and frames.
- [`locale-browser.js:initLanguageLinks`] never performs browser-language detection, local-storage preference reads, or redirects. It only removes a legacy `lang` query parameter with `history.replaceState` and maintains stable German/English paths.
- [`function-tour.css:data-tour-ready`] and [`function-tour.css:data-tour-state`] keep tour controls hidden until the runtime is ready and reserve the pinned layout for an active tour; [`supporters.css:data-supporter-controls`] keeps unnecessary logo controls hidden.

## Side Effects

- [`render.ts:renderTemplate`] and [`i18n-html.ts:loadCatalog`] read templates and JSON catalogs from disk through `node:fs/promises`; the renderer returns HTML strings and does not write files or persist application state.
- [`seo.ts:renderSitemap`] and [`seo.ts:renderSeoTags`] construct XML/HTML strings in memory. They do not perform network requests or filesystem writes.
- [`main.ts`] registers HMR cleanup handlers, queries the document, and dynamically imports supporter and tour modules. Import failures are logged while the static supporter list or written tour explanation remains available.
- [`locale-browser.js:initLanguageLinks`] mutates language-link `href` values, may clean `window.history`, and installs hash-change and click listeners. The returned abort function removes those listeners.
- [`experience.js`] may replace the current URL for legacy homepage section hashes, adds Web Animations API effects, updates `aria-current`, and listens to scroll, resize, and reduced-motion changes.
- [`hero-loading.js:scheduleHeroVideo`] installs load, scroll, visibility, and cancellation listeners and schedules animation frames; it does not set a video source when reduced motion, Save-Data, a slow connection, a hidden tab, or an off-screen hero blocks startup.
- [`supporters.js:initSupporters`] installs abortable click, keyboard, scroll, resize, and `ResizeObserver` handlers and calls `scrollBy`/`scrollTo`; its cleanup aborts listeners, disconnects the observer, cancels a pending frame, and hides controls.
- [`function-tour.js:initFunctionTour`] creates GSAP timelines and a ScrollTrigger pin, mutates the tour DOM and scroll position, updates progress/accessibility text, and responds to pointer, keyboard, visibility, resize, and motion-preference events. Its returned cleanup aborts listeners, releases the pin, reverts media contexts/timelines, and removes the readiness marker.
- [`site.js:#mobile-menu`] toggles menu visibility and ARIA state, applies `body.style.overflow`, changes `inert` on background elements, traps focus, and animates open/close. [`site.js:htmx:responseError`] writes server error text into a status region. [`site.js:data-hero-video`] assigns video sources, calls `load`/`play`/`pause`, performs frame-gated fades between playlist clips, and [`site.js:giveUpToFallbackInitial`] restores the poster after all initial candidates fail; it exposes a non-UI `window.__heroVideo` test hook.
